# HepatiQ Team Workflow

This project is a student team project, so we keep the workflow simple, professional, and easy to follow.

## Main idea
- Keep `main` as the stable branch
- Work on your own feature branch
- Open a pull request before merging
- Keep changes small and easy to review

## Branch naming
Use a simple name that tells what you are working on.

Good examples:

```bash
meet-backend
nirali-ml
rudra-validation
deekshitha-frontend
```

You do not need to follow a very strict format. Just make it readable and consistent.

## Workflow
1. Start from `main`
2. Create a branch for the task
3. Make your changes on that branch
4. Commit clearly and keep messages short but useful
5. Open a pull request when the work is ready
6. Ask a teammate to review it
7. Merge after checking the changes
8. Delete the branch once it is merged

## Pull request expectations
Every PR should be simple and focused.

Include:
- what changed
- why it was needed
- what was tested or checked
- anything a teammate should know

## Review expectations
- try to review each other's work when possible
- keep the review short and practical
- do not merge without checking the code
- keep one PR focused on one task

## Direct push policy
We prefer not to push directly to `main`.

If something urgent happens, it is okay to fix it quickly, but the correct process is still:
- make a branch
- do the fix
- open a PR

This keeps the project clean and avoids breaking the main branch for others.

## Merge style
Use the simple approach:
- squash merge for small fixes and feature work
- normal merge when the history is useful
- keep the repo easy to understand

## Team spirit
The goal is not to create a heavy corporate process. We just want a workflow that is:
- clear
- lightweight
- easy for students to follow
- safe for the project

This is enough for a healthy team project without making things complicated.
