# Proposed Correction: Hardcoded Calibration Plot

**Status:** proposal only; not implemented in the research branch  
**Severity:** P0 integrity issue  
**Separate branch:** `fix/calibration-plot-integrity`  
**Do not mix with:** feature-ablation and imputation experiments

## 1. Current defect

`src/hepatiq/validation/calibration_plot.py:11-13` contains hardcoded arrays:

```python
prob_true = np.array([0.05, 0.15, 0.25, 0.35, 0.45, 0.65, 0.85])
prob_pred = np.array([0.08, 0.18, 0.24, 0.32, 0.42, 0.68, 0.82])
ax.plot(prob_pred, prob_true, 's-', label='Logistic Regression (CV)', markersize=8)
```

The plotted points are not computed from model predictions or outcomes. The
script can therefore generate a calibration figure that has no relationship to
the model. No committed PNG exists, but the script remains a misleading
artifact and must not be used as evidence.

The file is excluded from coverage in `pyproject.toml:42`, so no test currently
detects the hardcoded data.

## 2. Proposed correction

### 2.1 Reuse genuine out-of-fold predictions

`src/hepatiq/validation/run_validation.py` already provides:

```python
def out_of_fold_predictions(features: pd.DataFrame, target: pd.Series):
    """Return (model_oof, prior_oof) probability arrays, one value per patient."""
```

The corrected script should:

1. Load `PROCESSED_DATA`.
2. Build features and target with `build_feature_frame`.
3. Call `out_of_fold_predictions(features, target)`.
4. Use `model_oof` and `target.to_numpy()` to compute the reliability curve.
5. Save the figure to `CALIBRATION_PLOT_PATH`.
6. Print the number of patients, event count, and the curve points used.

No synthetic or hardcoded probabilities are permitted. If OOF predictions are
unavailable or invalid, the script must fail with a clear error rather than
fall back to placeholder data.

### 2.2 Extract a testable pure function

Add a pure function to the module, for example:

```python
def reliability_curve(y_true, y_prob, n_bins=10):
    """Return (prob_pred, prob_true, counts) using quantile bins."""
```

Requirements:

- validate equal lengths;
- validate probabilities are finite and in `[0, 1]`;
- validate both classes are present;
- use quantile bins (`strategy="quantile"`) so each bin has comparable size;
- return the bin counts so sparse bins are visible;
- raise `ValueError` for invalid input.

`main()` then becomes a thin I/O wrapper around `reliability_curve`.

### 2.3 Plot requirements

- Perfect-calibration diagonal from 0 to 1.
- Observed versus mean predicted points for the OOF curve.
- Bin counts annotated or printed.
- Axis labels with units.
- Title: `Reliability Diagram - HepatiQ OOF Predictions`.
- Caption or printed line stating the number of patients, number of events,
  and fold scheme (`5-fold stratified, seed 42`).
- Do not label it `Logistic Regression (CV)` unless the predictions are
  actually OOF; use `Logistic Regression (OOF)`.

### 2.4 Tests

Add `tests/test_calibration_plot.py`:

- exact known input produces expected bin counts and points;
- invalid shapes, NaNs, out-of-range probabilities, and single-class labels
  raise `ValueError`;
- `main()` does not contain literal `prob_true`/`prob_pred` arrays;
- `main()` calls the OOF provider and raises if it returns an empty array;
- output path is written in a temporary directory during the test.

Remove `src/hepatiq/validation/calibration_plot.py` from the coverage omit list
after the test exists.

## 3. Acceptance criteria

- No hardcoded calibration points remain anywhere in the repository.
- The figure is computed from genuine OOF predictions.
- The script is deterministic for seed 42.
- The test suite covers the pure function and the failure modes.
- The committed figure, if any, is generated by the corrected script and
  accompanied by a note that it is OOF calibration on the 329-patient cohort.
- Documentation no longer implies a calibration figure exists until the
  corrected figure is generated and reviewed.

## 4. Rollout

1. Review and approve this proposal.
2. Create `fix/calibration-plot-integrity` from `main`.
3. Implement the pure function, corrected `main()`, and tests.
4. Run `pytest`, `ruff`, and the corrected script.
5. Inspect the generated figure and summary counts.

## 5. Non-goals

- This proposal does not recalibrate the model.
- It does not change the deployed model or risk thresholds.
- It does not decide whether the model is well calibrated; it only ensures the
  calibration figure reports real OOF data.
